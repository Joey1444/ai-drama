# 第 1 环：剧本与编排 + 分发

> 调研日期：**2026-10-09**（所有星数/更新时间为当日现查；星数会漂移，引用时请标注日期）
> 服务对象：零编程（靠 Claude Code 代写代码）、本机 AMD 780M 核显无 CUDA、已确认 RunPod + MiniMax H3 可用、预算敏感可付费。
> 本环范围：创意 → 分集剧本 → 分镜表(shot list) 的自动化；成片后**批量导出**与**多平台尺寸适配**（9:16 / 16:9 / 1:1）；多平台分发。

---

## 0. 一句话结论

- **剧本→分集的"文字层"已基本可全自动**（LLM 一步到位，质量可用，成本极低）。
- **分镜表(shot list)可半自动结构化**：LLM 能产出 JSON/Markdown 分镜，但**"跨镜人物/场景一致性"和"台词时长 vs 镜头时长"两处必须人工把关**——这是全链路的第一个硬卡点。
- **一站式整合型项目已经出现**（本环最有价值）：Pixelle-Video(28.8K)、waoowaoo(14.4K)、影策(1.2K)、aid-studio(837)、MoneyPrinterTurbo(129K)。但它们**面向"文案/解说/漫剧"更快**，面向"真人连续剧"仍偏半自动。
- **多尺寸适配无"无损全自动"方案**：只有"图文解说"类能靠重生成/裁剪做到三比例全自动；复杂多镜头短剧只能"每比例重生成"或"裁剪+人脸追踪"，都要人工验收。
- **分发层**：国内平台无官方发布 API，只能**浏览器自动化**（social-auto-upload, 15.4K）；国际平台走 **Postiz**(36.9K) 这类 API 调度器更稳。
- **对零编程用户的最优本环入口 = `zenstory-ai/drama-skills`**（Claude Code/Codex 技能包，无需 GPU，Windows 原生可跑，只需本机装 ffmpeg）。

**关键事实（drama-skills，一手 README 抓取）：**
- 事实源是**五份 Markdown**：`剧本.md / 视觉设定.md / 分镜.md / 图片提示词.md / 视频提示词.md`(+`剪辑单.md`)——无数据库，改文件即改决定，**极适合零编程用户维护**。
- **跨镜一致性靠"文件事实 + 校验脚本"**：造型写成可原样贴进提示词的"连续性锁"短语，漏了会被 `creator_markdown_check.py` 报错（README 给了真实报错样例）。
- **"确认后生产"闸门**：任何图片/视频/配音/音乐任务先预览内容与参数，用户明确确认后才调外部接口花钱。
- **不支持 GPU 也不自建模型**：本地只跑确定性检查脚本；生成媒体走外部 adapter（供应商凭据放项目外）。
- 实测数据：MiniMax H3 中文约 **4.1 个可发声字/秒**（对白估时依据）；示例使用 20 章原著→分镜 20 镜→成片，视频生成成本约 **40 元**。

## 6. 四类短剧在本环的难度差异

| 短剧类型 | 本环（剧本→分镜）难度 | 原因 | 本环现成工具 |
|---|---|---|---|
| **① AI 真人风** | **中** | 文字层同其它类；难在"真人连续性"——同一张脸/服装/年龄跨镜保持，纯文本分镜管不住，必须靠**参考图/首尾帧**锚定，H3 六段式提示词要写清说话人绑定 | drama-skills（图生视频模式）、影策、aid-studio、waoowaoo |
| **② AI 动画/漫剧** | **低-中（本环最成熟）** | 二次元/漫画风对"一致性"容忍度高，参考图体系天然适配；剧本→分镜的 skill/流水线最多 | drama-skills、aid-studio、影策、ComfyUI-H3-Prompt-Builder |
| **③ 图文解说** | **最低（可近全自动）** | 不需要复杂分镜；主题→文案→配图→配音→字幕→合成一条龙，比例也能原生生成 | MoneyPrinterTurbo、Pixelle-Video、story-flicks、video-recap-skills |
| **④ 混合（真人素材+AI 特效/生成）** | **最高** | 本环要额外产出**混合时间线/EDL**：真人片段与 AI 镜头如何交替、特效轨如何叠；现成工具都假设"单一来源"，无整合方案 | 无专门工具；只能用 影策/aid-studio 的时间线 + ffmpeg 手工编排 |

**难度排序（本环）：图文解说 ≪ 漫剧 ≲ AI 真人 ≪ 混合。**

## 7. 本环的"卡点"——哪里无法全自动、必须人工介入

1. **跨镜视觉一致性（最大卡点）**：文本分镜无法保证同一角色/场景/道具跨镜不漂移。drama-skills 的解法是"连续性锁短语 + 校验脚本报错"，但**仍需人工出参考图或人工验收**；纯自动 = 会漂。
2. **台词时长 vs 镜头时长**：LLM 估时不准（H3 中文≈4.1 字/秒），过密会**赶词/静默截断**；分镜必须先估时再定镜长——**需要人工判断"是否拆镜/延长"**。
3. **口型落到错误人脸**：说话人与画面正脸不匹配是常见故障；分镜要显式交代"画内/画外 + 谁闭嘴"，**生成后仍需人工核对**。
4. **"确认后生产"闸门本身是人工环节**：付费生成前置人工确认（drama-skills/drama-skills 刻意设计如此），去掉它就等于无人值守烧钱+抽卡。
5. **多尺寸无无损全自动**：复杂多镜头短剧无法一次生成适配三比例；要么**每比例重生成（成本×N、结果不一致）**，要么**裁剪（丢内容、需人脸追踪）**，两种都需人工验收。
6. **分发层的登录态/验证码**：国内平台浏览器自动化**必然**需要人工处理登录与风控，无法真正无人值守。
7. **合规标识**：AI 生成内容的显式标识需人工添加/确认。
8. **工程集成卡点**：一站式项目（waoowaoo/影策/aid-studio）部署后**仍要人工配模型渠道/API Key**，且部分（waoowaoo）已转 source-available 许可，商用前需读条款。

## 8. 对本用户（零编程 / 无 CUDA）的推荐路径

**本环首选：`zenstory-ai/drama-skills`（2,663⭐，MIT）**
- 完美贴合：**Claude Code 技能包**（本用户已在用 Claude Code）→ **零编程**；**无需 GPU**；**Windows 原生可跑**（作者 CI 在 Windows 回归）；本机只需装 **ffmpeg/ffprobe**。
- 直接对接本用户的 **MiniMax H3**：内置 H3 六段式方言与"挂参考图计划"，且提示词可"我自己挂图"，不强绑供应商。
- 成本可控：示例成片约 40 元；"确认后生产"闸门避免乱烧钱。
- 维护成本低：项目事实就是几份 Markdown，改文件即改决定。

**补充组合：**
- **图文解说类**想全自动一条龙 → 加 **MoneyPrinterTurbo**(129K⭐) 或 **Pixelle-Video**(28.8K⭐)（都支持 9:16/16:9/1:1，GPU 非必须）。
- **漫剧整站式**（要图形工作台+时间线剪辑）→ **影策 open-ai-canvas**(1,158⭐,MIT) 或 **aid-studio**(837⭐,MIT)，放 Linux 云服务器（可 RunPod）自部署；不选 waoowaoo 作首选（Elastic License + Preview 期）。
- **分发** → 国内用 **social-auto-upload**(15.4K⭐)；国际用 **Postiz**(36.9K⭐,AGPL) 做定时队列。
- **多尺寸** → 图文/漫剧走"原生多比例生成"；真人/混合走**裁剪+人脸追踪**（clippyme / AI-Youtube-Shorts-Generator）或 ffmpeg 加边。

**最省事的起步动作**：本机装 ffmpeg → 在 Claude Code 里 `npx skills add zenstory-ai/drama-skills -y` → 用 drama-skills 写第 1 集剧本+分镜 → 提示词对接 MiniMax H3 生成 → 用其 edit 技能借 ffmpeg 剪成片 → social-auto-upload/Postiz 分发。
