# 第 6 环：剪辑合成与字幕（自动拼接 / 转场 / 字幕 / 烧录 / 导出）

> 调研日期：**2026-10-09**（所有星数与更新日期均为当日实测）
> 服务对象：清华 SIGS 材料硕士，零编程（但用 Claude Code 代写），**无 CUDA**（AMD 780M 核显），Windows 11，已确认可用 **RunPod + MiniMax H3**，目标"不限于科研、赚钱优先"。

## 0. 一句话结论

本环**技术上是"最成熟"的一环**（FFmpeg 生态极为稳定，字幕有现成 ASR），但**"全自动"的天花板卡在"剪辑感"（节奏、转场时机、口型/音画同步）**——这一段机器能做 80%，剩下 20% 的"像人剪的"必须人工微调。
**最大惊喜**：已有**整合型项目**把这一环包进端到端流水线，且**专为 Claude Code 设计**：`OpenMontage`（65.7k⭐，AGPL-3.0）——它把 FFmpeg+WhisperX+Remotion 封成 agent 工具，正是"用 Claude Code 全自动出片"的现成答案。
**最大卡点**：① **AI 真人风的口型同步**（无全自动方案）；② **配音时长 ≠ 生成片段时长**导致音画漂移；③ **中文字幕断句**无高星专库；④ 多个好项目是 **CC BY-NC-SA（禁商用）**，与"赚钱"目标冲突。

## 1. 本环在总链路中的位置

```
[1剧本] → [2分镜] → [3图像] → [4视频生成] → [5配音/TTS] → ┌─────────────────────────┐
                                                          │ 6. 剪辑合成与字幕（本环） │
                                                          │  a. 片段拼接 + 转场       │
                                                          │  b. 字幕生成/对齐（ASR）  │
                                                          │  c. 字幕烧录/样式         │
                                                          │  d. 导出成片 + 尺寸适配   │
                                                          └─────────────────────────┘
```

本环四个子任务与代表工具：

| 子任务 | 说明 | 主力工具 |
|---|---|---|
| a. 拼接+转场 | 把 N 个镜头片段接成一条，加 xfade/交叉溶解/运镜节奏 | **FFmpeg**（xfade/concat）、MoviePy、Remotion、Editly |
| b. 字幕生成/对齐 | 语音→文字→时间轴；或直接用剧本文字+对齐 | **faster-whisper / FunASR / WhisperX**（词级时间戳） |
| c. 字幕烧录 | 把字幕印进画面（硬字幕），中文换行/标点 | **FFmpeg `subtitles=` 滤镜**、libass；剪映内建 |
| d. 导出适配 | 竖屏 9:16 / 横屏 16:9 / 1:1，码率、平台规格 | FFmpeg 导出 profile；Remotion/Shotstack 多平台模板 |

## 6. 四类短剧在本环的难度差异（核心）

| 类型 | 拼接+转场 | 字幕生成 | 字幕烧录 | 导出 | 本环总体难度 | 症结 |
|---|---|---|---|---|---|---|
| **1 AI 真人风** | 🟡 中（要卡口播节奏） | 🟢 易（有 TTS 文本，直接对齐） | 🟢 易 | 🟢 易 | **🔴 最高** | **口型同步（lip-sync）无全自动**；AI 生成片段时长短/口型漂移 |
| **2 AI 动画/漫剧** | 🟡 中（转场要有"番剧感"） | 🟢 易（剧本文字直出） | 🟢 易 | 🟢 易 | **🟡 中** | 观众对动画**口型容忍度高**（配音即可），难度显著低于真人；难在"节奏/分镜感" |
| **3 图文解说** | 🟢 易（图+图切换） | 🟢 极易（旁白文本=字幕） | 🟢 易 | 🟢 易 | **🟢 最低（已解决）** | 无实质卡点；MoneyPrinterTurbo/AutoClip 全自动 |

## 7. 本环的"卡点"——哪里无法全自动、必须人工介入

1. **口型同步（类型 1/4 头号卡点）**
   AI 生成片段里人物说话，但嘴型与配音**对不上**。现成方案：Wav2Lip（老、质量低）、MuseTalk/SadTalker（需调参、易糊脸）、Kling Lip Sync（云、按量付费）。**没有"一次跑对"的全自动方案**，几乎都要人工挑片段/重跑。

2. **配音时长 ≠ 视频片段时长（音画漂移）**
   TTS 配音 8.3 秒，但视频生成器给 8.0 秒 → 累积错位。自动补救只有硬手段（变速/补帧/裁掉尾帧），**"自然地对齐"仍需人工判断**。这是全类通病，类型 1/4 最痛。

3. **中文字幕断句 / 标点**
   高星 ASR 给的常是**段落级时间戳**（whisper 系），断句与标点靠模型猜；**没有高星专用中文断句库**（见 §3 注）。需用 FunASR（自带标点+VAD）或 SubtitleEdit 的中文断行，仍常需人工微调。

4. **"剪辑感"无法自动化** ⚠️ **本条 2026-10-10 已修正，见下方**
   转场时机、镜头停留长短、BGM 卡点、节奏起伏——**这是审美，不是算法**。Auto-Editor/PySceneDetect 只能切"静音/画面变化"，切不出"戏"。所有一键成片工具都承认需要"人工微调分镜"（BigBanana 明说"不是点一次按钮就出爆款"）。

   > 🔁 **修正（2026-10-10）**：上面这条**只对"从原始素材里剪"成立**——那时素材没有既定用途，
   > 留哪段扔哪段确实靠审美。
   >
   > **但 AI 短剧不是这个场景**：我们**先有分镜，后有镜头**。分镜里已经把剪辑决策写死了——
   >
   > | 分镜里的字段 | 它决定的剪辑参数 |
   > |---|---|
   > | 每镜**时长** | 时间轴与节奏曲线（ASL） |
   > | **声音**列（低频轰鸣/脚步声/敲门声/心跳） | 低频垫底区间、转场音效、静音刀位置 |
   > | 画面里的**「画外」**标注 | **J-cut（声先入）** |
   > | **景别**列 | 切点选择 |
   > | **风险**列 | 哪几镜要掐得更紧 |
   >
   > 所以对本项目而言，**剪辑感不是审美，是分镜的既定参数，可以 100% 自动推导**。
   > 落点：`scripts/make_edit.py`（分镜 → `edit.json`）→ `_validate/build.py`。
   >
   > **教训**：引用文档结论前先看它**前提适不适用**。这条被我当成"剪辑无法自动化"的依据用了半天，
   > 而它讨论的是完全不同的工序。

5. **剪映 v7+ 无法自动导出**
   `pyJianYingDraft` 的批量导出**只支持剪映 6 及以下**；想用新版剪映丰富模板 → 得走 `CapCutAPI/VectCutAPI`（有云端渲染）或退回纯 FFmpeg。

6. **Windows 下 FFmpeg 中文字幕烧录的坑**
   `subtitles=` 滤镜依赖 fontconfig，中文常遇**字体找不到/GBK 乱码**；路径含中文/空格要转义。属于"配一次就好"，但零基础会卡。

7. **许可陷阱（对"赚钱"目标致命）**
   `huobao-drama`、`BigBanana` 是 **CC BY-NC-SA 4.0 = 禁止商用**；`OpenMontage` 是 **AGPL-3.0**（商用需开源衍生/合规评估）；`banana-slides` 是 AGPL-3.0。**要商用优先选 MIT/Apache**：MoneyPrinterTurbo（MIT）、AutoClip（MIT）、LocalMiniDrama（MIT）、Toonflow（MIT）、Pixelle-Video/OpenStoryline（Apache-2.0）。

8. **未查到 / 需实测**
   - 剪映/CapCut 2026 年**官方会员条款与免费额度定量**（未查到权威原文）。
   - Descript/Kapwing **API 现价**（未查到）。
   - 部分 ComfyUI 字幕节点（`ComfyUI_ASSSSA`、`ComfyUI-VideoOverlayFFmpeg` 等）**无星数统计**，为小仓库。

## 8. 针对本用户的推荐路径

**总原则**：本机（AMD 780M，无 CUDA）可完成**剪辑、字幕、烧录、导出**全部工作（FFmpeg + whisper.cpp/faster-whisper 都是纯 CPU）；只有"AI 生成 + 重对齐模型"丢 **RunPod**。

### 路径 A（推荐起点，最快见效）：图文解说 / 混合的自动化
- **底座**：`FFmpeg`（拼接+转场 xfade+烧字幕+导出） + `faster-whisper`（CPU 出词级 SRT）→ 让 **Claude Code 写成一个脚本**，一条命令跑通。免费、可批量、不受剪映版本/会员限制。
- **省事备选**：直接上 `MoneyPrinterTurbo`（MIT，129k⭐，图文解说全自动）或 `AutoClip`（MIT，桌面版+字幕+发布文案）。
- **接入云**：中转 → `RunPod + MiniMax H3` 出片段，回到本机交给 FFmpeg 合成。

### 路径 B（最有想象空间）：Claude Code 直接驱动的一站式
- **`OpenMontage`（65.7k⭐）**：把 Claude Code 变视频工作室，字幕/烧录/混音/口型/多平台导出全含，**无 GPU 也能跑通**。**先小样验证**（AGPL-3.0 许可先看清楚），确认它在本机的可用性。
- **`jianying-editor-skill`（3.8k⭐，Claude Skill）+ `pyJianYingDraft`（4.5k⭐）**：想借剪映的模板/花字，用自然语言驱动剪映完成装配（注意 v7+ 导出限制）。

### 路径 C（如果你要多类型"混合"且想要中文最优）
- **字幕**：`FunASR / FunClip`（中文标点+时间戳最准，CPU 可跑）。
- **整合**：`LocalMiniDrama`（MIT，最接近"一键短剧"，含导出解说 SRT）或 `DramaClaw`（6.8k⭐，剧本→成片）；**避开 CC BY-NC-SA 的两个项目**。

### 第一步的最小可验证动作
> 在本机装好 `FFmpeg` + `faster-whisper`，让 Claude Code 写一个 `build.sh`：给一段测试视频 → 自动出 SRT → 烧进字幕 → 导出 9:16 竖屏 MP4。**验收标准：命令跑完得到一个带中文字幕的竖屏成片文件。** 这一步跑通，本环就"已打通"，后面只是换成自动化编排。
