# MiniMax H3 能力地图（RunPod 实测）

> **2026-10-10** ｜ 起因：此前用 H3 是"打一枪换一个地方"，撞见两个本该一开始就知道的资产
> （turbo LoRA 已挂没生效、单次多镜从未用过）。此文是**系统性侦察**的结果，先于动手。
> 所有结论**均在本 Pod 上实测或从工作流原件读出**，不是推测。

## 〇、先看全局：Pod 上有 772 个 H3 自定义节点 ★

`object_info` 实测：这台 Pod 的 ComfyUI 装了 **772 个 `MiniMaxH3*` 系节点**。
我们此前只用了一个工作流里的十来个。按能力家族归类（节点名清单存 `docs/调研/H3资产/h3_node_names.txt`）：

| 家族 | 节点数 | 代表 | **对我们的价值** |
|---|---|---|---|
| 📹 **长视频/续接** | **143** | `LongVideoPlanner/Orchestrator`、`Continuation*`、`Outpaint*`、`Chunked*`、`Temporal*` | **突破单段时长**——做真正的长镜头，而不是硬拼 |
| ⚡ **加速** | **139** | `SPEED*`、`HyperFlow*`、`PDD*`、`FastH3V2*`、`Progressive*`、`TwoPass*`、`Turbo*` | 比 turbo 更快的路径（**我们只用了 turbo 一个**） |
| 🎭 **音色/对白** | **65** | `VoiceProfile`、`VoiceLibrarySave/Load`、`SpeechStudio`、`DialogueScript`、`SpeechVerify` | **解决"声音债"**——跨镜音色一致 + 对白校验 |
| 🧑 **人脸精修** | **66** | `FaceRefine*`（一整套）、`SkinFinish*`、`FaceCharacterProfile`、`MultiFaceComposite` | 脸崩/质感补救（**后期级**能力） |
| 💾 存取/状态 | 37 | `*Save/Load`、`Checkpoint`、`Resume`、`Workspace` | 断点续跑（省钱） |
| 🩺 诊断/审计 | 36 | `*Audit`、`Preflight`、`QualityGate`、`Verify` | 自动质检（**可接我们的 Gate**） |
| 🖼️ **关键帧/参考** | **33** | `MultiKeyframeConditioning`、`FiveView*`（五视图）、`TimedImage/VideoReference`、`KeyframePlan` | 一致性 + 角色三视图 |
| 🎬 导演/编排 | 31 | `Director`、`Studio`、`Timeline`、`ShotSelect`、`CreatorRunReceipt` | 分镜级编排 |
| 🔧 画质/超分 | 26 | `DLSSNR*`、`FlashVSR*`、`RealBasicVSR*`、`Topaz*`、`DenseLearnedUpscale` | **768p → 更高**（我们一直靠 ffmpeg 硬放） |
| 🎛️ 采样/调度 | 22 | `DualClockSampler`、`DynamicCFGGuider`、`SigmaShift`、`AVSigmaTailSubdivision` | 画质/稳定性调参 |
| 🧠 提示词/文本 | 16 | `PromptCompiler`、`PromptBudgetCompiler`、`PromptRewriter8B`、`PromptSemanticContractAudit` | 提示词自动编译/审查 |
| **注意力/显存** | ~18 | `SageAttention`、`SolAttention`、`FlashAttention`、`LowVRAMAttention`、`BlockSparse` | 省显存（4090 也能跑） |
| **运动控制/修复** | ~13 | `MotionContext*`、`MotionRepairPlan`、`MotionRetiming`、`MotionSegmentPlan` | 运动连贯与抖动修复 |
| 📐 几何/构图 | 12 | `*Composite`、`*Mask`、`RAFTMaskPropagation`、`NativeMaskedVideoContext` | 局部重绘 |
| 🎵 MV/音乐 | 5 | `MVVocalLock*`、`MVRef2VAPromptCompiler` | MV 形态（新内容形态） |
| 其他 | ~110 | `TRTVAE*`（TensorRT）、`Avatar*`（数字人）、`FunControlNet`、`Meridian*`、`SelectiveRepair*`、`SourceControl*` | 探索性 |

> **结论**：我们此前对 H3 的使用是**"用一个玩具的一颗螺丝"**。
> 尤其 **长视频（143）**、**音色/对白（65）**、**人脸精修（66）**、**超分（26）**
> 四块，直接对应我们的四个已知痛点（时长硬拼 / 声音债 / 脸崩 / 768p 糊）。

## 二、工作流结构（从原件读出）

### `video_minimax_h3_r2v.json`（参考式）
```
127 UNETLoader(ref2va) ─┬─> 141 ComfySwitchNode ─> 126 BasicGuider
                        └─> 145 LoraLoaderModelOnly(ref2v_turbo_4step)
                                 └─> 141.on_true
146 PrimitiveBoolean ──> 141.switch 和 142.switch   ★★ turbo 总开关
143 PrimitiveInt[20] ──> 142.on_false
144 PrimitiveInt[4]  ──> 142.on_true
142 ComfySwitchNode  ──> 124 BasicScheduler.steps
```
**★★ 关键**：`146` 是 master turbo 开关。
- `False`（**此前一直如此**）→ 裸模型 + **20 步**
- `True` → turbo LoRA + **4 步**

**改法（API 格式）**：`payload["prompt"]["146"]["inputs"]["value"] = True`

### `t2v-pod.json`（文生）—— 比 r2v 多一堆 H3 专用优化节点
| 节点 | 作用 |
|---|---|
| 145 `SpectrumApplyMiniMaxH3` | 频谱加速 |
| 185 `MiniMaxH3MemoryEfficientSageAttentionPatch` | SageAttention 省显存 |
| 187 `MiniMaxH3SigmaShift [12, 3]` | sigma 调度微调 |
| 188 `MiniMaxH3MemoryEfficientSolAttentionPatch` | SolAttention |
| 192 `MiniMaxH3ChunkFeedForward [True, 2, 8192]` | 分块前馈（省显存） |
| 196 `CreateVideoExternalFFmpegNVENC` | 硬编码出片 |

⚠️ 但 `191 Lora Loader (LoraManager)` 的值是**空的** → **t2v 路径没挂 turbo LoRA**（想加速得手动挂 `fl2v_turbo_4step`）。

## 三、H3 官方支持、本项目从未用的能力

### 3.1 参考系统（**远超"2 张图"**）★

从 `object_info` 读出 `MiniMaxH3ReferenceToVideo` 的真实接口：

| 输入 | 类型 | 说明 | 用了没 |
|---|---|---|---|
| `ref_images` | **COMFY_AUTOGROW_V3** | **自动增长列表 → 不限张数**（降到 2048 短边，不放大） | ⚠️ 只用 2 |
| `ref_videos` | 视频参考 | 参考原视频的**运镜、剪辑、节奏、时间结构**；可"从原视频结尾继续" | ❌ |
| **`ref_audios`** | **音频参考** | **参考说话人音色与语速**（不复制原信号）、BGM 风格、节拍 | ❌ **完全没用** |
| `ref_video_audios` | 参考视频的同步音轨 | —— | ❌ |
| `ref_image_size` | 必填 | 参考图缩放档 | ❌ 从没设过 |

**`<Audio N>` 关系标记**（官方 `ref-en.txt` §4.2）：
`fully_copy`（1:1 用作成片音轨）· `partially_copy` · **`reference`（只参考音色/节奏/风格，不复制信号）** · `weak_reference`

> ★ **直接命中项目已知痛点**：文档记的"**声音债**——跨镜音色会漂"。
> `<Audio 1> is the voice-timbre reference for <Subject 1> (S1).` + `reference` 标记即可锁音色。
> 另有 **`<Video N>`**：可"从原视频结尾继续"、参考其运镜与剪辑节奏。
> `summary` 可组合任务前缀，如 `[video editing + reference generation + audio reuse]`。

## 四、性能实测

| 配置 | 采样式 | 20 步耗时 |
|---|---|---|
| Ref2VA **双参考** | **39 秒/步** | ≈ 13 分钟 |
| Ref2VA 单参考 | 9 秒/步 | ≈ 3 分钟 |
| ⚠️ 双参考显存 | **31.7 / 32GB**（5090 贴顶） | —— |
| ⚠️ 切换模式 | fl2va ↔ ref2va 每次**重载 20GB 模型**（+1–2 分钟） | —— |

**推算（待 turbo 实测确认）**：若 4 步 turbo 成立，双参考应从 13 分钟降到 **≈ 2.6 分钟**。

---

**实测确认（同日 09:41 提交 → 09:45 完成）**：4 步 turbo 双参考 **≈ 3.5 分钟**，
对比 20 步的 13 分钟 → **快约 3.7 倍**，画质（场景锁定 / 脸一致 / 无 logo / 冷调）**肉眼与 20 步版相当**。
→ **结论：此后一律开 turbo。**

## 五、由此得到的做法规矩

1. **开跑前先翻 turbo 开关**（`payload["prompt"]["146"]["inputs"]["value"]=True`）——省 ~3.7 倍时间，此前全浪费了
2. **同模式的镜批在一起跑**（避免反复重载 20GB 模型）
3. **环境镜只用单参考**（只需场景锚）→ 显存与时间都省
4. **连续镜优先用官方多镜合成**（少一次调用 + 零跨镜漂移）
5. **要锁什么，什么就必须进参考图**（脸/服装/道具）；提示词的否定句压不过参考图
6. **动手前先 `ls` 模型目录**——Pod 资产会变，文档会过期

## 七、实验计划（按"改变做法"的程度排序）

**P0 —— 直接改变 E1 重做的做法**
1. **单次多镜**（1 次 2 切实验）→ 若成，13 镜可压成 8–9 次生成，跨镜零漂移
2. **音色参考**（`ref_audios` + `VoiceProfile`）→ 锁跨镜音色
3. **多张参考图**（≥3）→ 同时锁服装+道具+场景

**P1 —— 提速与提质**
4. turbo vs `pdd_acc` vs `hyperflow` vs `FastH3V2` 四路加速对比（谁最快且画质够）
5. 超分链路（`DLSSNR` / `FlashVSR`）替代 ffmpeg 硬放
6. `FaceRefine` / `SkinFinish` 对人脸的改善

**P2 —— 探索性**
7. `LongVideo` / `Continuation`：真长镜头
8. `FiveView`：一键角色三视图（替掉我们手写的定妆提示词）
9. `PromptCompiler` / `*Audit`：接进我们已有的 Gate

> ⚠️ **每个实验都必须先明确"判据是什么"**，否则又是一轮打一枪换一个地方。
