## A. AI 工程专家意见

### A1 ｜~~「RunPod 自跑 H3」是伪命题~~ → **❌ 已推翻：用户是对的，H3 确实已开源**

**原指控**：H3 是闭源商业 API、无开源权重，RunPod 跑的是 Wan2.1 等开源模型 → 降本线塌方。

**核实结果**（2026-10-09 联网检索）：**指控不成立**。

- **MiniMax H3 已于 2026-08-03 开源权重**，两个 checkpoint：`FL2VA`（文生 / 首帧 / 尾帧 / 首+尾帧）与 `Ref2VA`（参考式生成，支持图/视频/音频）
- **保留原生音频**（这是方案的核心卖点，成立）——官方原话：
  - 「768p video with **native stereo audio**」
  - 「**32 kHz stereo, generated in the same pass**」
  - 「single-stream packed-token diffusion transformer that **denoises video and stereo audio latents jointly**」
- **RunPod 有官方部署文档**，四个已测 GPU 档：

  | GPU | 显存 | 定位 |
  |---|---|---|
  | RTX 3090 / 4090 | 24 GB | 最低成本 |
  | RTX 5090 | 32 GB | 低显存 Blackwell |
  | **L40S** | 48 GB | 更高质量/更长视频（官方推荐默认） |
  | RTX PRO 6000 | 96 GB | 最高质量与速度 |

  原文：「**All four templates generate video with audio**」；「Initial startup can take several minutes while the container and models download」
- HuggingFace 有社区量化版（`leejet/MiniMax-H3-GGUF`、`Abiray/Minimax-H3-nvfp4-INT4-INT8-Convrot`）——侧证权重公开且社区已在本地跑
- 模型体积：diffusion 61.7GB(bf16) → 19.5GB(pruned int8)；text encoder 48GB(bf16) → 14.6GB(nvfp4)

**专家为何会错**：其依据 `3-关键帧出图与图生视频.md` 把 H3 标为「商业 API / ✅ 纯云」——**该调研文件过时且错误**（开源发生于 2026-08-03，调研未覆盖）。

**风险点已转移**（新的核查优先级）：
1. **许可能否商用** —— 授权为 **MiniMax H3 Community License**，公开页未展开商业条款。**这直接决定这条路能不能赚钱，是现在的第一优先核查项**
2. **成本模型重算** —— 自跑后成本 = GPU 租金 × 时长，不再是按秒 API 费；方案 §4 的 −76~86% 需按实测吞吐重算
3. **能力对等性** —— 开源版 768P vs 云 API 2K 的画质/质量差距，以及 RunPod 冷启动与储物柜闲置成本

### A2 ｜「自锚定」与自身调研结论矛盾【已验证：成立（但方案已部分自我修正）】

**指控**：`2-角色一致性.md` 第 93 行白纸黑字：「参考图要人工筛选…**禁用随机生成帧当参考**」，而方案 §3-A5 把"抽第 1 镜帧当后续 R2V 参考"列为零平台核心手段。

**我的核查**：属实。但需公平指出——方案 A5 已加了「不盲抽说话帧，人工挑正脸/闭嘴帧」的限制，不是纯随机。**分歧在标准高度**：调研要求「正面/45°侧/微表情/标准光照 4 张」，挑一帧生成图达不到。方案 §0 把自锚定标为「一致性最弱」仍属低估，实为「大概率不可用」。

### A3 ｜$0.08/s 成本底座未证实，且可能查错域名【已验证：核查缺口属实】

**指控**：全案成本压在这个数上，但它只来自 ofox.ai 二手；且方案查的是 `platform.minimax.cn`（国内站只列 TTS），调研文件用的是 **`platform.minimax.io`（国际站，有 video-generation 文档）**——两个域名很可能不是同一计费页。

**我的核查**：`3-关键帧出图与图生视频.md` 第 21 行引用的确实是 `platform.minimax.io/docs/guides/video-generation`，而方案附录 C 写的是「MiniMax 官方定价页 仅列 TTS」查的是 `.cn`。**指控成立，这是个真实的核查缺口**，且是可立刻补的。

### A4 ｜build.py 吃不下未知规格的 H3 产出【已实测复现 → ✅ 已修复并验证】

**指控**：硬编码 + 无音轨镜必崩 + 字幕路径转义。

**我的实测**（造一个无音轨镜头跑 build.py）：
```
Stream specifier ':a' in filtergraph description ... matches no streams.
Error binding filtergraph inputs/outputs: Invalid argument
```
**确认崩掉**。另核查代码属实：
- 第 19 行硬编码 `FPS=25`、第 61 行硬编码 `sample_rates=32000`，与 docstring「任意尺寸/帧率」承诺冲突
- 第 58–62 行对每个镜头**无条件**构造 `[{i}:a]aformat=...` → 任一镜无音轨即整条崩
- 第 80–81 行 `subtitles='{rel}'` 的路径转义在**中文/空格文件名**下会炸（现能跑只因路径碰巧是纯 ASCII）

**修复**（build.py v2）：
- 逐镜 `ffprobe` 探测宽高/帧率/有无音轨，不再硬编码 `FPS=25`
- 无音轨镜**自动注入 `anullsrc` 等长静音**
- 字幕改以 `subs/` 为工作目录、用纯文件名，绕开中文/空格路径的转义地狱
- 帧率取自首镜实测值而非写死

**修复后验证**：
- 正常 3 镜 → 14.20s / **-13.9 LUFS** / **aac 32000Hz** / 退出码 0
- 含无音轨镜 → 16.80s / aac 32000Hz / 退出码 0
- 正常路径输出**字节数与修复前完全一致**（683673 B）——确定性未受影响

> 📌 **一条专家建议被实测证伪**：专家建议「去掉 loudnorm 后重复的 `aresample=32000`」。实测那**不是冗余**——删掉后输出采样率变成 **96000Hz**。已改回。
> **教训：专家意见必须逐条实测，不能照单全收。**

## B. 漫剧制作人意见

### B1 ｜选题与账号定位全空白 —— 「漫剧」是形态，不是题材【成立，且优先级最高】

方案通篇写「先做 AI 漫剧/图文解说」，但**没有一处回答**：做什么题材、面向谁、靠什么变现（广告/带货/付费/私域）。技术跑通 ≠ 有人看。**先定「一个账号 = 一个题材 = 一个钩子模板」**。

### B2 ｜平台 AI 限流与商业闭环未验证，而它才是「赚钱」的第一前提【成立】

方案 §8 把「平台 AI 风控/限流、AI 感判非原创降权」放在**停止信号**里——等于默认先花几个月跑技术、再撞市场。而 2026 AI 标识是合规必加，加了大概率进低流量池。**建议：第一步不是装 ffmpeg，是先用小号发 3–5 条同题材 AI 内容实测起号**。这条证伪，前面全白做。

### B3 ｜系列化 / IP 沉淀空白 —— 短剧赚钱靠追更，方案只做了「单集」【成立】

规格通篇是「单集 60s/10 镜」，跨集锁脸需 LoRA（4–8h/角色）根本没进主线。而短剧收益模式（免费前几集→付费解锁，或涨粉接广告）核心是 **30 集起的追更**。**先定系列 IP，再反推技术选型**，而不是「先跑 1 集再说」。

### B4 ｜「1–3h/集人工」不可压缩，量产前提不成立【成立】

10 个必人工环节里，漂移抽检、台词时长、情绪抽卡、节奏微调四项**每集重复且不可并行**。方案自己写的「人工 1–3h/集」意味着**一天产不出 1 集**。建议把定位从「无人值守量产」诚实改为「AI 批量初剪 + ~1h/集人工精修」，按此重算日更上限。

### B5 ｜60s/10 镜与 H3 能力上限自相矛盾【成立】

10 镜平均 6s/镜，贴着 4s 下限，每镜无表演空间；60s 至少要 4–6 段拼接，接缝处运动是模型脑补。**应改「少镜长镜」——6 镜/集、每镜 8–10s**。另外「60s 短视频引流」与「1–2 分钟付费短剧」是两个不同规格，方案混成了一个，**必须先二选一**。

## C. 我的综合判断

**技术侧**：方案的技术主线（H3 云 API）**没崩**，崩的是**降本路线**（RunPod 跑 H3）。A1/A4 是硬伤，A3 是可立刻补的核查缺口。

**内容侧**：B1–B3 是**比技术更根本**的盲区。用户的目标是赚钱，但方案通篇在解"怎么做出来"，没解"做出来给谁看、怎么变现"。技术链路跑得再顺，选题和平台这两条不成立就是空转。

**两位专家的共识**：都指向「方案把技术可行性当成了项目可行性」。
