# 制作约束（分层：模型限制 / 部署约束 / 项目默认）

> **什么时候读**：写剧本、分镜、视频提示词之前。
> **来源**：`docs/评审/审核意见-双专家.md` 的 producer 评估 + **2026-10-10 对官方规范的复核**。
>
> ⚠️ **2026-10-10 重要修正**：本文件此前把三类**强度不同**的东西混标成「H3 硬限制」。
> 复核官方 `h3-prompt-writing` 规范后拆成三层——**别再混着用**（详见文末「复核记录」）。

---

## 第 1 层：H3 模型本身的限制（换分辨率/换平台也不消失）

| # | 约束 | 依据 | 强度 |
|---|---|---|---|
| 1 | ⚠️ **多主体同框不可靠**（含双人对话） | 多主体在 H3 上可靠度低；且与本项目 `Ref2VA` **单主体**参考方式冲突 | 强（模型级 + 与我们参考方式冲突） |
| 2 | ⚠️ **画面内可读文字 / UI 会糊** | 生成模型的通病，非 H3 特有，但确实做不好 | 强 |
| 3 | ⚠️ **原生音轨 ≠ 口型准确** | 事实基线；依赖精确口型的特写念白不可靠 | 强 |
| 4 | ⚠️ **单镜台词 ≤ 1–2 句** | 长对白是口型/节奏重灾区 | 中 |
| 5 | ⚠️ **跨镜一致性弱**（模型无跨镜记忆） | 事实基线；需外部锚点（关键帧/参考图） | 强 |

## 第 2 层：本地部署的约束（换托管 API 2K 即解除）

| # | 约束 | 依据 | 换掉什么就解除 |
|---|---|---|---|
| 6 | ⚠️ **远景 / 大场面会糊** | **本地开源部署只出 768p**（竖屏 768×1366），远景细节不够 | 走**托管 API 2K**；或改构图（主体压中轴、减少环境信息量） |
| 7 | ⚠️ **单段时长上限** | 托管 API 4–15s 整数秒；本地实测 20s 可出 | ⚠️ **非硬墙**——官方规范支持**一次生成内做多镜**（`[Shot 1]…[Shot 2] At 00:05.000, the camera cuts to…`），等于绕开单段限制 |

## 第 3 层：本项目的保守默认（可被创作者一句话覆盖）

| # | 默认 | 为什么这么定 | 怎么覆盖 |
|---|---|---|---|
| 8 | 禁复杂动作 / 追逐 / 打斗 | 跨镜一致性与动作衔接代价高，**当前产能下不划算**；不是做不出 | 拆解成"手/物/局部"的可见状态链，或上 2K + 多镜 |
| 9 | 角色 ≤ 2–3 人、造型一次锚定、禁频繁换装 | 跨镜漂移控制 | 上 LoRA / 关键帧链路后可放宽 |
| 10 | 景别以特写/近景为主 | 768p 下保险；也是《符》的窄场景定位 | 走 2K 后可用 `medium-wide`（**官方示例自己就用了 `medium-wide shot`**） |

> **一句话**：第 1 层是「H3 做不好」，第 2 层是「我们本地这台机器做不好」，第 3 层是「我们现在不想做」。
> **别把第 2、3 层当成模型天花板到处传播。**

## H3 做得好的（沿用）

- 单人情绪镜头
- 手 / 眼 / 器物特写
- 极简场景
- 氛围空镜

## 未来感的取巧法

**科技感靠「信息密度」，不靠「场景密度」。**

- 后期叠 UI / HUD / 扫描线 / 字幕（ffmpeg 可做）
- 统一冷调色 + 霓虹色块
- **声音设计**：环境音、提示音、低频——**这是最廉价的未来感**
- 台词写未来黑话 / 去人称
- 极简构图：空房、单人、留白
- **屏中屏**：主角对设备 / 屏幕独白

## 机器校验

`python scripts/check_script.py <剧本路径>` 自动检查第 1 条（同框风险，按在场说话人统计）与第 4 条（台词容量）与连续性标注。
⚠️ 它**不检查**第 2、3 层（分辨率/场面规模）——那两条要人工或按项目定位判断。

## 复核记录（2026-10-10）

**触发**：用户质疑「禁大场面是不是最新的 MiniMax H3 要求」。

**核查**：
1. 官方 `h3-prompt-writing` 规范（`references/base-en.txt`）**没有**任何"禁远景/禁大场面/禁群戏"表述；
   其**自己的示例使用 `medium-wide shot`**（L81、L175），且**明确支持单次生成内多镜序列**。
2. 本文件旧版把「禁群戏/大场面/未来都市远景」标为硬限制，理由写「768P 下远景糊」——
   但 768p 是**本地部署**分辨率（托管 API 为 2K），**不构成模型限制**。
3. 旧版标注的来源 `docs/评审/审核意见-双专家.md` 中**查无此条**——引用不成立。

**结论**：该条是**项目内部保守默认**，被误标成「H3 硬限制」。已按上述三层拆分。
**待核实**：多主体同框（第 1 层第 1 条）在 **2K + 多镜**下是否同样不可靠——需一次实测，勿凭推测下结论。
